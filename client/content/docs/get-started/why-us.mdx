## The problem with existing tools

Most webhook inspection tools do one thing: give you a URL and show you raw JSON. That's useful for five minutes. It breaks down the moment you're:

- Managing multiple projects or integrations
- Trying to reproduce a bug from a request that fired 2 days ago
- Working with binary uploads, form data, or XML payloads
- Sharing a request with a teammate to debug together
- Needing to forward the request to your local dev server while also capturing it

hooklex is built for the full debugging workflow, not just the first step.

## Built for real debugging workflows

### You don't just want to _see_ the request. You want to _work_ with it.

Other tools treat the request as a log entry. hooklex treats it as a **workable artifact**:

- **Replay it** — resend the captured request with `?isReplay=true&replayedFrom=<your_custom_label>` to instantly tag and identify your re-run in the UI header and search history
- **Share it** — make it public and hand the link to a teammate *(Cloud Version — Coming Soon)*
- **Export it** — drop it into a report, a spreadsheet, or your notes
- **Type it** — convert the body to TypeScript so you can code against it immediately

### Your workspace scales with your projects

Flat request lists get unmanageable fast. Collections let you organize by project, client, environment, or integration — the same mental model you already use in Postman, but for incoming traffic.

### How the isReplay System Simplifies Debugging

Traditional debugging tools make it difficult to locate and trace re-executed test requests amidst thousands of incoming events in a busy log history.

**hooklex** allows you to **manually replay** any captured request while tagging it directly in the UI dashboard. To initiate a replay with visual tracking, append two dedicated query parameters to your webhook endpoint:

```text
?isReplay=true&replayedFrom=<your_custom_label>
```

| Parameter                          | Description                                                                                                                                                                                                         |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| isReplay=true                      | Instructs hooklex to display a prominent REPLAY badge in the sidebar request list, making test runs instantly distinguishable from live incoming traffic.                                                          |
| replayedFrom=`<your_custom_label>` | A user-provided identity label displayed prominently at the top of the request summary. It lets you instantly recognize the origin of the re-run and search for it directly without digging through parameter tabs. |

Because these parameters surface key metadata directly in the UI, you can quickly locate, identify, and debug replayed requests in active developer environments

<Callout type="warning">
  Both isReplay=true and replayedFrom must be sent together. Omitting either
  parameter causes the request to be rejected with a `400` Bad Request.
</Callout>
