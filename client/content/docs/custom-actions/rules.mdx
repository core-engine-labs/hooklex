**Condition actions** allow you to apply logic before executing subsequent actions like [Forward Request](/docs/custom-actions/forward-request) or [Custom Response](/docs/custom-actions/custom-actions-response). A condition determines whether pipeline execution continues based on the content of the incoming request.

<Callout type="warn">
  Condition Rules are a **paid feature available exclusively in the upcoming Cloud Version (Coming Soon)**.
</Callout>

## How the Execution Loop Works

Actions in **APP_NAME** execute sequentially in a defined pipeline order. A **Condition** action must be placed prior to any action you want to protect.

```text
Action 1: Condition Action → PASS → Continue execution
Action 2: Forward Request Action → Executed
Action 3: Condition Action → FAIL → Pipeline execution breaks. Loop stops.
Action 4: Custom Response Action → (Never reached)

```

### Execution Order

| Step | What Happens                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------ |
| 1    | APP_NAME evaluates a **Condition action** in the pipeline sequence                                     |
| 2    | If the condition **passes**, APP_NAME proceeds to the next action (such as Forward or Custom Response) |
| 3    | APP_NAME continues down the action pipeline step-by-step                                               |
| 4    | If any condition **fails**, the execution loop breaks immediately                                      |
| 5    | All remaining actions below the failed condition are skipped                                           |

## Defining a Condition

Conditions evaluate criteria against the incoming request. You can configure rules targeting:

| Target           | Examples                              |
| ---------------- | ------------------------------------- |
| **Body**         | `body.event == "payment.success"`     |
| **Headers**      | `headers["x-api-key"] == "my-secret"` |
| **Query Params** | `query.env == "production"`           |
| **Method**       | `method == "POST"`                    |
| **IP Address**   | `ip == "203.0.113.42"`                |

## Supported Operators

A **Condition action** evaluates a request field against a value using one of the operators below.

| Operator     | Description               |
| ------------ | ------------------------- |
| `equals`     | Equals                    |
| `notEquals`  | Not equals                |
| `contains`   | String contains           |
| `startsWith` | String starts with        |
| `endsWith`   | String ends with          |
| `matches`    | Matches (regex / pattern) |

> **Note:** `matches` treats the value as a pattern — see examples below.

### Examples

```json
{ "field": "body.status", "operator": "equals",    "value": "paid" }
{ "field": "body.email",  "operator": "contains",  "value": "@example.com" }
{ "field": "body.id",     "operator": "startsWith","value": "usr_" }
{ "field": "body.file",   "operator": "endsWith",  "value": ".pdf" }
{ "field": "body.phone",  "operator": "matches",   "value": "^\\+?[0-9]{10,15}$" }
{ "field": "body.status", "operator": "notEquals", "value": "cancelled" }

```

## Example: Conditional Forward + Conditional Response

Here is a real-world example with chained pipeline actions:

```text
Incoming request → body.event = "payment.success"

Action 1 — Condition Action
  Rule: body.event == "payment.success"
  → PASSES → Continue to Action 2

Action 2 — Forward Request Action
  Target: [https://my-server.com/webhooks/payment](https://my-server.com/webhooks/payment)
  → Executed ✓

Action 3 — Condition Action
  Rule: body.amount > 1000
  → FAILS (amount is 50) → Pipeline breaks ✗

Action 4 — Custom Response Action
  Response: 200 { "vip": true }
  → (Never reached because pipeline broke at Action 3)

```

## Actions Without Prior Conditions

If an action does not have a preceding Condition action, it executes unconditionally when pipeline execution reaches it (provided no earlier condition broke the loop).

```text
Action 1 — Forward Request Action → Runs immediately
Action 2 — Custom Response Action → Runs if Action 1 completes

```

Use an unguarded Custom Response action at the end of your chain as a guaranteed fallback response.

## Tips for Designing Action Chains

- **Positioning is key.** Place Condition actions prior to the Forward Request or Custom Response actions they govern.
- **Failures halt execution.** Remember that a failed Condition action terminates the pipeline immediately; use fallbacks before any breaking condition if necessary.
- **Test incrementally.** Add actions one at a time and inspect APP_NAME's request logs to verify evaluation flow.
